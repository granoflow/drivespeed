# 设备信息、网友评测与综合分析

本段为报告输入与 Agent 流程；渲染器不安装依赖、不读设备、不联网。新增证据的中英文标签由report-templates/en.json、zh.json维护；其他语言由Agent按英文语义生成完整labels，不静默套用中文。

## 只读设备信息

新测速时由 Agent 按平台准备可信渠道的当前稳定版 smartmontools，检查已安装版本及上游版本后按需安装/更新，记录实际版本与来源；离线或权限不足据实说明，不宣称已是最新版。工具支持 macOS、Windows、Linux，不等于 DriveSpeed 三平台实机验收已完成；Linux/Windows仍遵守现行实验性边界。

macOS 可用 Homebrew，Windows 使用上游发布的安装包，Linux 使用发行版可信软件源。不要静默装包管理器、启用 smartd 常驻服务或改驱动。系统要求管理员授权时遵循实际授权，不能把权限失败当设备故障。

先从选定磁盘映射到真实物理设备并确认身份，针对该设备执行 `smartctl -x -j <device>`，保留返回码/读取警告和实际采集时间。只读身份/健康信息不授权自检、修改设置、固件更新或原始设备写入；不要运行 `-t`、`-s`、`--set` 等改变状态的选项。读取失败或字段部分可用时保留未知及原因，不能填0或把命令非零退出全部当作无数据（smartctl使用状态位）。型号/容量不符时先解决目标绑定，不附入本盘报告。

整理固件型号、固件版本、容量、协议、SMART状态、温度、备用空间、寿命百分比、通电、异常断电、介质错误、错误日志、主机读写累计等可用字段。标明单位；原NVMe data units换算按协议，不与NAND写量混用。0错误或寿命整数0%不是全盘完好或全新证明。缓存字段若未公开，在对话说明“标准读取未提供缓存配置”，报告省略该字段，不能写“无缓存”。序列号、WWN/EUI、GUID、完整路径不进入模板或搜索词。

表格位于报告标题下方。scope保存是否与测速同时采集，实际采集时间保留为元数据；scope解释和固件数据可信边界只在对话展示。后来只读的快照不得称为测速时温度。型号/容量/固件和SMART均可能被篡改，不能独立证明真伪。

## 最多10条原始评测

联网能力可用时以型号、容量、接口、硬盘盒/主控等公开线索搜索并打开原文，保留真实结果，不用搜索摘要猜数。先匹配同型号与容量，再按接口及实际协商速率、硬盘盒主控、主机/系统、软件/参数、空闲空间/预处理等相近程度排序。不要把仅有系列名的主控当成确认变体。相同文章的转载去重，不凑满10条；超过10条才选最接近10条，review_selection说明检索范围、缺项与选择理由，无网络时如实说明。

每条必填label（清晰来源名或原文标题）、HTTPS直达链接和实际查阅日期；title仅为可选展示标题。其余型号/容量、接口、盒子主控、软件、条件、结果及对照按原文可取得的资料选填，未知项直接省略。价格/宣传峰值不冒充测量。不同接口的同盘测试可以解释能力边界，但不与本机相除得“性能损失”；不同盘的同盒数据仅为链路背景，不能放进本盘评测列表。

统一解读已保存的快速/深入/历史测量，逐项保留方法、时间、工作集和状态。先解释本次顺序吞吐、低队列表现、持续吞吐与缓存可观测性，再回答升级收益与质量疑点。样本差异较大时先检查连接、容量版本、预处理、温度和测量方法；怀疑假货必须说明固件数据也可能伪造及尚缺独立证据，不因SMART通过排除造假。

## JSON输入

扩展既有绑定 run_id/language 的 `evaluation`，在内存中添加 `evidence`，随原有 `--evaluation-stdin` 输入。不改原始 results、缓存成公共产品资料或新增秘密文件。可填模板为 `assets/report-templates/evaluation.zh.json`；占位符必须由真实数据替换，不能直接作为事实渲染。

- `device_health`: `status`为collected/unavailable；`model`须与本次hardware.drive.model精确一致；`tool`为实际smartctl版本，`captured_at`为实际时间；`scope`解释采集范围或失败原因；`rows`只允许zh.json evidence.fields中的字段。unavailable保留空rows并说明原因。未知字段省略；身份、缓存缺项在scope和对话中说明，不渲染成表格行或脚注。
- `online_reviews`: 0–10条，按上述顺序已筛选的原始评测。渲染器拒绝超过10条、重复URL或非HTTPS地址，不静默截断。每项的`comparison`说明可比性和与本机实测的关系；仅comparison_status=supported时进入verified_only报告，否则在对话说明。review_selection中的搜索缺口也仅进对话。
- `review_selection`: 可选的对话研究记录；没有资料时可说明未找到/无法检索、日期及范围，不暗示已搜遍网络。
- `further_testing`: 可选结构化建议，decision为not_recommended/recommended/uncertain；reason说明实测、来源和判断，remaining_unknowns说明仍未确认什么，when_to_continue说明何种具体目标值得另测。仅用于交付对话，不进入verified_only报告，不自动改变实测资格或启动任务。

中英文可直接使用语义模板标签；其他语言须提供evaluation.evidence.labels，其键与英文模板evidence完全一致（包括fields和deep_decisions），只翻译文字值；缺键或空值会拒绝，不回落英文/中文。没有evidence的既有语言输出不受影响。结构验证不能替代Agent的数值和来源核查。只重生成时复用已保存快照、链接、日期，除用户明确要求更新外不重读当前设备或重搜网络。

## 快速结果后的深入测试决策

先展示快速顺序与4 KiB QD1随机四项结果，说明随机项实际字节与持续时间；最多16MiB或5秒先到停止，不把短样本写成长时间延迟稳定性结论。先完整初始化1GiB再读取/随机访问，初始化不完整就停止，不能用稀疏未写区域充当盘速。quick v2与旧两项的quick v1分别识别，不回填历史随机结果。

复用有效网络研究，不足时先定向补查同型号/容量、最接近接口和主控的评测。结合用户目标作建议：

- **建议到此为止**：只想了解当前日常顺序/随机性能；有效结果与已知路径及可比资料相符，没有具体异常；长写对该目标增量小，特别是外置路径低于参考原生持续写能力、可能遮蔽缓存边界时。交付快速报告与理由，不例行追加“是否全测”问题。
- **建议深入**：有明确未回答且full方法能增加证据的问题，例如队列深度、混合读写、实际长写表现。写明目的和限制，用一次有限计划邀请并等待同意；如果要解决的是缓存边界而当前路径/固定小工作集不适合，提出适合的问题和后续方法，不能照旧长写并承诺找缓存。
- **依据不足**：来源条件不明、随机测试缺测、异常或干扰尚未排清，先陈述缺口并做已授权低成本只读核查；不为凑完整推荐直接长写。

“外置路径可能遮蔽缓存差异”不等于缓存没有作用或设备无缓存；不能从官方峰值或一次短测就宣布该设备永远不需要深入测试。温度/恢复/剩余空间等变化、持续负载需求、特定异常或容量完整性目标出现时重新判断。用户主动要求深入仍可按有限计划执行；推荐停止不把quick变成full合格，也不解除现行容量检查的前置条件；投稿则按四项核心及必要设备/条件/私有身份字段另判，不由quick/full标签或背景状态决定。

当前报告展示规则以 reporting.md 的“问题交付与重测”为准。further_testing 和未取得的字段仅作为对话决策材料；报告不展示缺测、资料缺口、无法确认或重新测试邀请。JSON模板中的needs_followup是默认保护，只有逐项核实后改为supported，不能为显示段落直接改状态。

## 灵活的评测内容块

统一官网公开评测列表的色彩、字号层级、间距、指标区和底部来源链接，不固定每篇评测必须测什么。每条仅必填url、label、checked_at；设备型号、容量、接口、主控、工具、测试条件和对照结论均为选填。没有资料的字段直接不传，不写“未知”“不适用”“未测得”占位，也不显示空标题、空指标框。

- `title`可覆盖列表标题；否则依次使用drive_model或来源label。`capacity`仅有已核实容量时提供。
- `context`为按原文实际内容组织的`[{"label":"连接方式","value":"USB4 40 Gb/s"}]`，也可写主机、系统、软件、工作集、温度等任意已知参数。旧interface/controller/tool仍兼容，仅传入时显示，避免与context重复。
- `measurements`仅放值得突出且原文测过的结果。每项label自行命名，value可为有限非负数字或非空短文本（例如范围、分位数或定性结果），unit可省略或用原文单位；qualifier可为exact/approximate/greater_than/less_than，省略为exact。未测数据不能填0；真实测得0可保留。32项为输入安全上限，不是展示目标；一般只突出几个最相关结果。
- `sections`为任意标题与段落组成的内容块，每项包含title、paragraphs和evidence_status。可仅讨论温度、功耗、复制、缓存恢复、延迟、实际场景等原文覆盖的内容，不要求“测试条件／原文测量结果／与本次关系”三段都出现。verified_only只渲染supported的块。缺乏可靠数值时可只有文字块，不强制做指标卡片。
- 旧conditions/results/comparison字段仍兼容且均选填；comparison仅comparison_status=supported时进入正式报告。新条目优先用sections，避免新旧字段重复输出。

执行Agent先核原文再决定哪些块有价值：数字型评测可只有指标卡；温度/功耗评测可用不同单位；只给实际体验的评测用文字；未覆盖本机条件则仅记录实际原文条件，不硬写差异百分比。选填结构不是允许虚构，来源仍须逐条核对；缺测与免责只在对话说明。JSON主模板给空数组作为可选入口，删掉也可，不把空数组当作待补任务。

官网色值与排版结构按本次来源对齐，本地报告继续使用离线系统字体，PDF保留可点击链接和可读原网址。
