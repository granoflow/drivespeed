# 测速方法与专业报告依据

本项目采用文件级、有限预算测试，适合有用户数据的本地内置或外置硬盘目录；不是整盘破坏性认证。fio 本身是测量引擎，设备状态、主机和连接决定可观察结果。物理依赖可完整识别的本地磁盘映像可做文件系统测速，但标为virtual；跨多盘则标为multi_device，不将其解释成单块硬盘速度。

## 测速前的其他进程读写检查

这是执行 Skill 的 Agent 必须完成的启动门槛；当前 `benchmark.py` 的设备锁只防止其他 DriveSpeed 运行，不检查外部进程，也不自动结束进程。`--dry-run` 的只读识别可以先执行，不能把预演成功当成此项检查通过。

1. **确认范围与活动。** 以本次 `target.physical_devices` 为范围，覆盖共享物理盘的其他分区、APFS 卷、多盘映射的每块底层盘，以及虚拟盘 backing file 所在物理盘；不能只检查测速目录。使用当前平台可用的只读磁盘活动工具，至少观察连续 5 秒，结合卷/路径映射确认进程归属。必须有采样期间的读写事件、字节增量或速率证据；仅有打开文件、累计 I/O 计数或 CPU 占用不足以判定正在读写。不能可靠关联到目标盘的活动保留为“归属待确认”，不能当成无关活动放行。
2. **列表后停止。** 发现任何其他进程在目标盘读写时，用用户当前语言列出 PID、进程名、读/写方向、采样窗口内字节增量或事件证据、关联卷/路径（未知项明确标注），并说明共享同盘的关系。请用户自行暂停/关闭相关应用或任务，或者明确授权代理结束列表中的指定进程。没有回复、拒绝授权、进程未退出或仍有读写时，停在这里，不创建测试文件、不启动 fio；不能只提示“可能影响成绩”后继续。只在其他物理盘上的已确认活动不阻塞本次测速。
3. **按指定授权结束。** 明确说明结束进程可能中断任务或丢失未保存内容；用户对测速、安装或预算的授权不涵盖此动作。“我自己关闭”也不授权代理 kill。仅处理用户明确同意的进程，动作前重新核对 PID、进程身份和目标盘关联，防止 PID 被复用。优先正常退出或发送终止请求，不扩大到同名进程、整个进程组或子进程树；强制结束需另有明确授权。系统关键进程、无法安全停止或会不断重启的服务保持阻塞，不能为通过检查反复 kill。
4. **重新采样再启动。** 用户关闭或授权结束后重新检查，至少连续两个 5 秒窗口都未观察到其他进程对目标盘的读写，并确认没有未解决的活动归属或可见性缺口，才可继续已获授权的测速。工具缺失、权限不足、输出不完整、无法覆盖目标物理盘或只能看到本用户进程时，说明具体限制并停止；不能把空输出当成空闲，不自行提权或索取密码。检查工具自身的只读采样活动可排除，其他后台服务不能仅凭名称或低流量被忽略。

每次新的测速运行都要紧接启动前复查，包括单独缓存专项、其他专项、重试和中断后恢复；等待用户、安装依赖或目标映射变化后，旧检查失效。依赖需安装时先单独准备完成，再检查并启动测速，不能让旧检查跨越安装阶段。只在本次对话保留必要的进程证据，不将其他应用的完整命令行或文件路径写入公开报告。通过只表示这些窗口内未观察到冲突，不保证后续始终空闲；开始后发现新的冲突时先停止本次测速并保留已有结果，再按上述流程处理。

## 维度与原理

1 MiB 顺序访问对应大文件吞吐；4 KiB 随机访问展示小块 I/O 的带宽、IOPS 和完成延迟分位数。QD1 与 QD16 对比请求并发，并保留 achieved depth，不能把配置 QD 当成实际队列深度。macOS 使用 posixaio，Linux 使用 libaio，Windows 使用 windowsaio；缺少引擎则拒绝，避免偷偷改成同步引擎。

初始化先对专属文件真正写入一遍，稀疏预设长度不算初始化成功。后续读取只读该文件。`io_size` 限制每项总 I/O，`runtime` 提供时间上限，不使用会循环覆盖预算的 time_based。70/30 随机混合保守地按全部 I/O 算入潜在写入预算，因此实际写入不会因为混合比例而超额。

`direct=1` 请求绕过 OS 文件缓存；无法排除 SSD 控制器/伪 SLC 缓存。`end_fsync=1` 请求最终同步，I/O 统计与进程总耗时均保留。主机缓存处理失败时不改用缓存模式冒充同一测试。工作集可以被重复访问，持续测试不等于全盘单次写入。

## 持续性能的数值

- 初始平均：第一个 5 秒内已记录样本的时间加权平均。
- 末段：最后三分之一时间，最多 30 秒；列加权平均和样本中位数。
- 最低连续 5 秒平均：仅有完整、连续采样窗口时计算，缺样不补零。
- 持续降速候选：前 5 秒之后，连续 10 个约 1 秒采样都低于初始平均的 70%；列首个候选时间、按带宽积分估算的累计字节和此后平均速度。
- 降幅：1 - 末段平均/初始平均，可为负（表示变快）。样本不足则留空，不伪造“缓存内/缓存外”两档数值。

上述阈值是本工具的可解释描述算法，不是 SNIA 稳态判定。降速点可能受温度、缓存整理、后台任务、供电和主机负载影响，不能据此确认 SLC 缓存大小。报告保持“缓存耗尽未确认”；“降速后速度”有数据时直接给数值。缓存外性能确认需要另有控制变量与更充分的持续写入证据。

可为用户目标增大文件、写入预算和持续时间，但先展示副作用。不同满盘比例、TRIM 状态、先前写入、空闲恢复时间、温度和线材会影响可比性，保持一致并记录未知项。工具不会自动擦盘、全盘预处理、改变 TRIM 或生成综合评分。

## 缓存专项的完成条件

`--profile cache` 使用新建普通文件、单遍顺序写入，跳过会预热缓存的初始化及其他写入项。文件/I/O 按缓存估计加后续观察量与余量制定，无可用估计时以 1 TiB 兜底；默认 1800 秒；按可用空间缩减，同时保留至少卷容量 10%、10 GiB 或文件大小 25% 的空闲空间。预算/时限是硬上限，不能保证所有设备都出现可观察的缓存边界。

初始前 5 秒需有至少 4.5 秒连续样本，单样本偏离均值不超过 10%。随后至少连续 10 个、覆盖不少于 9.5 秒的样本低于初始均值 70%，才认作持续降速候选。降速开始前的带宽积分为本次可用写缓存候选容量，不包含第一个低速采样间隔。降速后继续写入 30 秒，再检查最后完整 60 秒窗口：加权变异系数不超过 10%，线性拟合趋势在该窗口内的变化不超过均值 10%，每个样本仍低于初始均值 70%。通过后以该窗口时间加权均值给出缓存后速度估算；这些阈值是本工具的方法，不是行业认证。

监控直接用 fio 每秒累计写入字节与运行时差分，避免日志缓存导致无法实时判断；满足条件后向本次进程组发送 SIGINT，让 fio 输出最终 JSON 和带宽日志。只有完整最终输出且没有 I/O 错误才接收结果，最终分析再用保存的带宽日志核对。中断、数据缺失、短暂跌落后恢复、持续漂移都不能误判成功。

缓存容量描述本次条件下还能吸收的写入量，不是固定 SLC 芯片容量；后台缓存折叠、温度和主机/接口瓶颈都会影响表现。未观测到降速不能断言设备没有缓存，也不能把已写入量简单当缓存容量下限。参考 [Tom’s Hardware T500 实测方法](https://www.tomshardware.com/pc-components/ssds/crucial-t500-4tb-ssd-review/2) 的长时间写入思路，但本工具不擦盘预处理，仍保留对原因的限制。


缓存规划遵循“执行模型网络搜索 → 模型已有知识 → 1 TiB 兜底”，详见 [缓存规划](cache-planning.md)。有来源/知识估计时通过 `--cache-estimate-file` 输入，再按估计缓存量加稳定采样量与余量制定文件；1 TiB 仅是无可用估计时的兜底，不是硬盘缓存参数。所有参考值与实测值分别记录。
