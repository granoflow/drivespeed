# 报告分析与交付

适用于正常测速后的本地报告、只读解读已有结果和离线重生成。只重生成时使用保存的测量、硬件及来源，不采集当前设备回填历史，也不为导出自动联网研究；用户要求更新分析/购买建议时才核查相应新资料，并与原结论分开。容量检查的独立结果通过命令附入派生正常报告，不修改原始测速记录。

## 原始事实与评价

先核 results.json 的方法、outcome、completeness、measurement_quality 与真实停止原因。当前 v2 缺缓存后稳定写速时只能交未完成记录；历史 v1 不追改资格。时序缺失/不齐不能补点或填零，缺测与不适用分开说明；只有足够连续样本才有固定窗口或稳态结论。

按[评价规则](evaluation.md)在内存中形成绑定 run_id/报告语言的三项评价：瓶颈在哪里、更换有无收益、异常与质量疑点。用 Python API 或 `--evaluation-stdin` 输入，不创建评价 JSON 缓存。没有证据时回答仍须完整，但明确无法判断及下一项低成本验证，不编造健康分、假货结论或购买收益。

面向普通读者先给日常使用解读；完整数字保留在 HTML 技术附录。初始/末段/最低连续5秒/降速后速度按各自实际窗口解释，不把尾速改名为缓存后速度、峰值与平均拼接为同条件比较。Gb/s信号换算不是文件测速合格线，额定值与实测之差不是可追回收益，缓存参考不覆盖实测。

三维星级只在背景与参考证据满足[硬件评级规则](hardware-rating.md)时给出；其他情况描述本次主机路径结果。只显示本设备实际参数；有实证瓶颈与兼容收益依据时才给推荐设备参数，不展示整份接口速率目录或以候选/竞品冒充本设备。

## 导出与隐私

默认随对话语言、隐藏电脑型号，不主动问显示偏好。用户主动要求显示时才用 `--show-computer-model`；此选项控制本地 A/B HTML/PDF，不改变原数据/投稿/hash。原电脑硬件事实仍可能上传供内部存储，公共读取会隐藏它，不能说电脑型号不上传。具体字段规则见[CLI](cli.md)。

只重生成报告：

```bash
python3 scripts/report.py --input /path/to/results.json --output /path/to/new-report --language zh-CN --format html
```

上例只演示底层导出，不代表可省略最终评价。交付最终报告时，若输入已含匹配运行/语言的有效评价可直接复用；否则加 `--evaluation-stdin`，由 Agent 经子进程 stdin 传内存对象，用户无需填写 JSON。仅重新导出时复用或翻译原评价及来源，不声称重新核实；没有新测量就不更新硬件事实或原始结论。需要 PDF 时按请求加 `--format pdf`，使用已有 Chromium 导出。检查输出实际存在、数字/来源/语言/状态一致；PDF须实际查看排版，失败则交付 HTML 并说明手动保存方法。不给未生成文件的链接，不把静态数据检查称为真实操作验收。

报告保留项目公开链接和本地化介绍，离线阅读不调用外部服务。交付对话另行说明测试文件去向、空间未释放、清理失败及预算/时限等执行事项；报告正文保留影响判断的测量限制与真实错误，不堆清理提醒。

## 已有数据的用户修正

用户主动补充型号、环境或判断按[user-input](user-input.md)加入派生结果，保留原始观测与来源。泛 device_models 只展示，不自动改变接入接口事实。

若用户确认了检测之外的接入接口，测前用 `--interface-name`；测后只在用户确认的同run派生副本中以 `confirmed_interface` 写入 hardware.access_interface。原target.protocol保留；后续prepare/compare/report统一使用该副本，不覆盖raw，不改变旧冻结投稿或沿旧同意重传。未分类接口不靠速度猜分类，名称和内部链路/连接器形态分开；详见[硬件规则](hardware-rating.md)和[命令](cli.md)。

## 横向比较

使用同一冻结比较ID的typed事实与本次原始数据写评价，保留来源、取得时间和条件差异。少于3份同条件记录不算统计优势，记录数不等于独立设备数。接收响应已有参考可离线使用；新的网络刷新只在用户要求时发起。无样本或用户拒绝分享也照常交付本地测速报告及三项评价。具体比较、冻结与恢复由[社区流程](community.md)维护。
