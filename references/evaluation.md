# 瓶颈、升级与异常评价

测速后由执行 AI 阅读本次原始结果和有效参考资料，再写评价。脚本只校验运行/语言绑定并转义渲染，不冒充硬件诊断模型。评价不存入公开规格缓存，不随 skill 分发；新一次测试必须重新判断。联网能力可用时查询当前竞品、兼容性和测试条件，优先打开官网；没有资料则保留缺口，不用泛泛的“可能是假货”凑结论。

先读本次measurement_quality及completeness。非quiet、观察可见性不足或历史未记录背景时，三项仍逐一回答，但只能描述该主机路径的实测、可能影响与下一项验证，不作设备纯净星级、确定瓶颈/均衡或质量真伪归因。两个启动前quiet窗口也不是全程无干扰证明。核心partial不冒完整；缓存物理边界未观察到则给有限预算/窗口下的具体结论，不填缓存外数字。

## 必答三项

1. **瓶颈在哪里。** 分开评价峰值、低队列日常访问和长时间写入。标明已确认事实、推断与未知。最低额定值只是已知链路约束，不证明真实瓶颈部件；区分接口支持速率与实际协商速率。主控候选不能升级为确认型号。温度相关性不等于热降速因果关系。
2. **更换有无收益。** 查实际存在的替代品，给出型号、来源、主机/线材/接口/供电兼容性及测试条件。区分只换硬盘盒、换硬盘和同时换主机。说明可能改善峰值还是持续稳定性，不能把官网与实测之差当可实现收益。不可比测试不算提升百分比；若没有足够证据支持购买，明确暂不建议购买，先做低成本对照。报价未查证就不报价。
3. **异常与质量疑点。** 明确观察事实、严重程度、可疑原因、缺失证据及下一项检查。单次降速、低于宣传峰值、SMART 总体通过或型号字符串都不是质量/真伪证明。未运行校验写入后回读、全地址容量检查时，不声称验证了真实容量或数据完整性。记录的 fio 字节是已接受的主机 I/O，不是 NAND 写入证明。出现可复现回读错误、容量回绕/覆盖、身份矛盾或厂商鉴定问题时可提升警告；先区分线材、供电、桥接、固件、散热与介质。序列号保修核对只是证据之一，不是独立真伪鉴定。

排查按低成本只读核对 → 单变量有预算对照 → 必要时厂商支持/容量完整性验证排序。新写入、拆装、擦盘和购买不是生成报告的隐式动作，不自动执行。测试不充分时用“待排查”，不输出虚假的健康分或故障概率。

## 输入与重生成

正常 Skill 在内存中构建以下对象；经 Python API 或 UTF-8 标准输入传给渲染器，不创建评价 JSON 缓存。字段如下；所有可见文本使用用户指定报告语言：

```json
{
  "run_id": "从本次 results.json 读取",
  "language": "zh-CN",
  "sections": [
    {"kind": "bottleneck", "title": "瓶颈判断", "paragraphs": ["本次判断、依据和未知项。"], "sources": []},
    {"kind": "upgrades", "title": "更换设备是否值得", "paragraphs": ["兼容替代品、实际收益边界和建议。"], "sources": []},
    {"kind": "anomalies", "title": "异常与质量疑点", "paragraphs": ["已观察异常、证据强度和排查顺序。"], "sources": []}
  ]
}
```

每个 sources 项包括 `url`（HTTPS 原始页面）、`label`（清晰来源名）、`checked_at`（实际查阅日期）。无网络证据用空列表，不能虚构链接或日期。可使用有效本地缓存中的原始查阅日期。

```bash
python3 scripts/report.py --input /path/to/results.json --evaluation-stdin --output /path/to/final-report --language zh-CN --format pdf
```

上面命令由 Agent 以子进程 stdin 传入序列化后的内存对象（不通过 shell 拼接正文）；不能交互等待用户输入 JSON。旧 `--evaluation-file` 继续兼容已有使用者。

有比较 ID 时添加 `--comparison-id ID --community-state-dir /path/to/private-state`，A/B 会读取同一冻结事实。Agent 先用 `read_comparison` 读取 typed 事实，评价可引用已公开来源的原始链接/原查阅日期，并明确快照时点、可比条件与不足项。社区事实不等于当前实时公开资格；需要更新时由用户发起刷新。

评价也可放在内存派生结果的 `evaluation` 字段；原始 fio 结果不可改写。绑定不匹配会报错，防止套用其他运行或语言的建议。省略评价的底层渲染仍兼容旧结果，但执行 skill 的 AI 不应将其作为最终完整评价报告交付。脚本的结构验证不代表事实核验；交付前检查来源、数值、条件、离线链接与 PDF 排版。

## 面向两类读者的编辑检查

先给明确判断和行动优先级，再列证据与未确认项。短时 QD1、短时 QD16、持续写入分开呈现；平均速度必须写明是哪一项、哪个时间窗口。专业参数保留在表格和方法区，正文只解释影响理解或决策的术语。每种限制集中说明一次，不在摘要、图表、评价和页脚反复重复；删去泛泛的免责句，保留真实测量缺口及其具体后果。对证据不足的问题给出下一项可验证的检查，而不是只说无法判断。翻译沿用此结构，不复制本机结论。


## 硬件与整份报告星级

最终 HTML/PDF 会重新计算[三维能力利用率](hardware-rating.md)：相对主控、相对接口、相对硬盘各一组星级，并给一句话点评。五项原始数值保留。AI 三段评价解释参考性质、可能限制及升级收益；低利用率不等于差品质，单次偏差不证明真伪。先补查准确型号的官方规格，不编造未知星级。接口支持能力、系统报告段、当前协商段及厂商额定文件测速分别引用；只有主控名也可以查官网，不因硬盘盒商品名未知而忽略已确认主控。
