# 可选对话补充

由执行 AI 在对话中收集，CLI 与 HTML 不弹表单，不使用终端 input()。三项各自可填、可跳过；即使全部空白，正常交付基础报告。

## 对话流程

1. **设备型号**：查看本次 hardware 的未知型号和未确认候选，只询问设备品牌及具体型号，包括电脑、SSD、硬盘盒、主控以及线材/转接器等实际涉及设备。复用已确认回答，不重复询问，不把主控系列当盒子型号。
2. **测试备注**：设备型号得到回答或明确跳过后，单独邀请填写测试备注，例如环境温度、安装情况、导热垫、散热、供电及后台活动。已有明确备注时展示原文，允许用户保留、补充、修改或移除。
3. **展示报告**：备注得到回答或明确跳过后，将已有补充写入报告，检查结果并交付可打开的 HTML 链接或打开报告；用户要求 PDF 时同步生成。仅在后台生成文件不算展示报告。
4. **测后自我分析**：展示报告后，再单独邀请用户填写看完报告后的判断，例如怀疑的原因、使用感受、下一步想验证什么。收到分析后合并到本次补充数据，重新生成 HTML；已有 PDF 时同步更新并检查。交付更新后的链接。用户跳过则保留已展示的报告，不创建空分析栏目。

每次只问一类内容，不能将三项合并在一个问题中。回答型号只完成型号步骤，不代表跳过备注或分析。收到当前步骤的回答或明确跳过后，才能询问下一项；用户明确要求跳过全部剩余项时直接交付报告。等待回复期间可继续生成基础报告，但不能把未回复视为跳过，也不能提前询问自我分析。

复用已有明确陈述，不推断用户未表达的观点；有歧义时保留原文，例如“没有贴硅脂”不能自动改为“没有安装导热垫”。用户可在交付后继续补充；没有回复不算同意任何假设或补测。

用户文字保留原意，不擅自润色成技术定论。敏感内容在纳入报告前向用户提示其会出现在可分享的文件中。补充观点使用“用户判断”，不能冒充 AI、测量或厂商结论。新增信息如果影响原有判断，AI 需重新检查评价与来源（例如未装导热垫），原始数值保持不变。

## 数据和展示

保存本次运行专用的 UTF-8 JSON，不放入参考资料缓存或 skill 分发目录。支持部分字段；空字符串或空对象不展示占位。设备项使用自然语言标签，可覆盖任意实际涉及设备：

```json
{
  "run_id": "复制本次 results.json 的 run_id",
  "language": "zh-CN",
  "device_models": {"硬盘盒": "用户给出的品牌和准确型号"},
  "test_notes": "用户的测试备注，可含换行。",
  "self_analysis": "用户自己的分析，可含换行。"
}
```

使用已有报告入口：

```bash
python3 scripts/report.py --input /path/to/results.json --user-input-file /path/to/user-input.json --output /path/to/final-report --language zh-CN --format pdf
```

也可将此对象写入派生结果的 `user_input` 字段；不改写原始 fio 数据。运行 ID 和报告语言必须匹配，换语言需用户同意或按其语言要求翻译并保留原意。保留补充 JSON 以便重生成；后续补充时合并用户已确认的内容，只删除用户明确要求移除的项。

HTML/PDF 在硬件配置后显示“用户补充”，设备型号标“用户提供”，保留原始检测记录用于追溯。补充型号不自动覆盖检测值或视为官方核实，也不会自动刷新参考缓存；执行 AI 根据新的型号重新研究资料并修订评价。若与已检测型号冲突，展示差异并核对，不静默替换。

验证：跳过/部分填写/全部填写、其他设备标签、换行与特殊字符转义、运行或语言不匹配、用户分析与测量区隔。PDF 沿用报告打印流程，交付前确认补充内容完整可读。
