# 可选对话补充

由执行 AI 接收用户主动补充，CLI 与 HTML 不弹表单，不使用终端 input()。型号、测试备注和自我分析均非必填；没有补充也直接交付报告。

## 对话流程

1. 用户选盘后，自动识别本次目标、查阅同设备缓存及必要公开资料，确认具体写入计划并完成正常测速。缺型号先研究，无法确认保留未知；常规不追问设备型号、备注、测后自我分析、报告语言或是否显示电脑型号。报告随当前对话语言，电脑型号默认隐藏。
2. 完成评价后先展示可打开的正常测速 HTML；用户要求 PDF 时同步生成。只有目标安全或影响结果的实质矛盾无法自行核实时，才针对该矛盾提问。用户已主动提供的信息直接复用，不能要求重新填写。
3. 展示报告后仅按 [诊断边界](diagnostics.md#可选容量与读写完整性检查) 单独邀请可选“容量与读写完整性检查”，展示其占用、写入量、估计时间范围和已有数据风险，并取得具体有限计划授权；既有余额不足时，把预演提出的精确追加有限量包含在同一个可选检查问题中，明确同意后才能在原台账原子追加并预留，不另问调参问题。拒绝或未回答不执行；等待期间正常报告仍可用，不把未回答当作授权。检查命令自动保留独立 results/report，并生成含容量摘要的 `combined-results.json` 与 `combined-report/report.html`；检查后交付独立和派生报告。
4. 容量检查完成、拒绝或本轮不作决定后，符合公开质量要求时再按 [社区流程](../SKILL.md#可选公开与横向测评) 单独邀请可选公开，使用本人 X 链接。容量检查通过不是投稿条件；未做检查不能写成已通过。容量证据本轮留本地，公共投稿只含正常测速数据，不增加字段或沿旧同意改变投稿，也不声称网站已展示容量检查。没有公开答复或明确拒绝时保留本地报告，不发起登录或投稿。

用户随时可以主动补充设备型号、环境、备注或自己的判断；只将实际提供的内容写入 `--user-input-file`，重新生成报告并交付新链接，已有 PDF 时同步更新。不要用一轮固定问卷替代自动识别与研究，也不增加档位、文件大小、强度等调参问题。

复用已有明确陈述，不推断用户未表达的观点；有歧义时保留原文，例如“没有贴硅脂”不能自动改为“没有安装导热垫”。用户文字保留原意，不擅自润色成技术定论。敏感内容在纳入报告前向用户提示其会出现在可分享的文件中。补充观点使用“用户判断”，不能冒充 AI、测量或厂商结论。新增信息影响原有判断时，AI 重新检查评价与来源，原始数值保持不变。电脑型号只有用户主动要求才在本地报告显示，不能借自由文本绕过默认隐藏。

## 数据和展示

保存本次运行专用的 UTF-8 JSON，不放入参考资料缓存或 skill 分发目录。支持部分字段；空字符串或空对象不展示占位。设备项使用自然语言标签，可覆盖任意实际涉及设备：

```json
{
  "run_id": "复制本次 results.json 的 run_id",
  "language": "zh-CN",
  "device_models": {"硬盘盒": "用户给出的品牌和准确型号"},
  "test_notes": "用户的测试备注，可含换行。",
  "self_analysis": "用户自己的分析，可含换行。"
}
```

使用已有报告入口：

```bash
python3 scripts/report.py --input /path/to/results.json --user-input-file /path/to/user-input.json --output /path/to/final-report --language zh-CN --format pdf
```

也可将此对象写入派生结果的 `user_input` 字段；不改写原始 fio 数据。运行 ID 和报告语言必须匹配，换语言需用户同意或按其语言要求翻译并保留原意。保留补充 JSON 以便重生成；后续补充时合并用户已确认的内容，只删除用户明确要求移除的项。

HTML/PDF 在硬件配置后显示“用户补充”，设备型号标“用户提供”，保留原始检测记录用于追溯。补充型号不自动覆盖检测值或视为官方核实，也不会自动刷新参考缓存；执行 AI 根据新的型号重新研究资料并修订评价。若与已检测型号冲突，展示差异并核对，不静默替换。

文档与报告自查：无补充直接交付、仅主动补充/部分填写/全部填写、其他设备标签、换行与特殊字符转义、运行或语言不匹配、用户分析与测量区隔。PDF 沿用报告打印流程，交付前确认补充内容完整可读。
