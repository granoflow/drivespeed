# 可选对话补充

由执行 AI 接收用户主动补充，用户补充环节不在CLI与HTML弹表单，也不使用终端input()追问；写入确认仍按[命令](cli.md)处理。型号、测试备注和自我分析均非必填；没有补充也直接交付报告。

## 对话流程

1. 用户选盘并明确要求测速后，Agent静默执行 `--stage quick --dry-run` 核对，再在1GiB文件、最多1040MiB写、90秒总采集保护内正式采集顺序写读和4KiB QD1随机读写。不问是否预演，不让用户填写路径、额度或档位；只要求查看计划时不实测。复用当前请求覆盖的快速测试授权，以当前hash确认，不追加常规问题。
2. 先展示可打开的快速实测HTML和真实速度、停止原因，研究对照后给是否值得深入的建议；无需深入时交付并停止追加测速，值得时才邀请；分享另按所需数据项及当前同意处理。快速结果不当作完整缓存测量。拒绝或未答就保留结果，不继续写入或重跑quick；用户要求PDF才生成。型号缺项自动识别、研究，无法确认保留未知；不逐项追问型号、备注、自我分析、语言或显示偏好，电脑型号默认隐藏。
3. 深入测试同意前说明实际占用、单次最大写量和总超时保护；默认full为8GiB文件、最多写1TiB、43分钟跨全部采集保护。使用：“这项测试需要较长时间，难以精确预计。我们把总超时保护设为43分钟；超过这个时间上限，程序将自动停止，并按已测得的数据生成报告。” 这是上限保护，依赖准备和等待确认不计入，停止采集后才清理并渲染，不承诺报告也在43分钟内完成。同意后显式 `--stage full`，不重新做quick；单次保护不延续历史余额，不自动重试。
4. 深入报告交付后，只有来源完整、目标及有效实测速度满足条件，才按[诊断边界](diagnostics.md#可选容量与读写完整性检查)邀请容量与读写完整性检查。一个问题展示范围、占用、本次写入量、估计时间范围及已有数据风险，取得独立单次计划同意；不提前提醒该可选步骤，不询问额度参数。拒绝或未答就跳过，保留报告；执行后交付独立及包含容量摘要的派生报告。
5. 本地报告交付后，按[社区流程](community.md#投稿所需数据项)核对四项核心及必要设备/条件/私有身份字段；齐全即可准备冻结预览或单独邀请分享，不按quick/full、原方法partial或背景状态否决。容量检查不是投稿资格条件，未做不能写成通过；容量证据留本地。发布必须取得本次预览的独立同意，未回答或拒绝时不发起登录或上传；规则变化及旧同意不覆盖新报告。

只有目标安全或影响结果的实质矛盾无法自行核实时才针对性提问；复用已明确的信息，不要求重新填写。旧SQLite历史只读保留，不删除或重置，也不把它的余额作为新测试的阻断。

用户随时可以主动补充设备型号、环境、备注或自己的判断；只将实际提供的内容写入 `--user-input-file`，重新生成报告并交付新链接，已有 PDF 时同步更新。不要用一轮固定问卷替代自动识别与研究，也不增加档位、文件大小、强度等调参问题。

复用已有明确陈述，不推断用户未表达的观点；有歧义时保留原文，例如“没有贴硅脂”不能自动改为“没有安装导热垫”。用户文字保留原意，不擅自润色成技术定论。敏感内容在纳入报告前向用户提示其会出现在可分享的文件中。补充观点使用“用户判断”，不能冒充 AI、测量或厂商结论。新增信息影响原有判断时，AI 重新检查评价与来源，原始数值保持不变。电脑型号只有用户主动要求才在本地报告显示，不能借自由文本绕过默认隐藏。

## 数据和展示

保存本次运行专用的 UTF-8 JSON，不放入参考资料缓存或 skill 分发目录。支持部分字段；空字符串或空对象不展示占位。设备项使用自然语言标签，可覆盖任意实际涉及设备：

```json
{
  "run_id": "复制本次 results.json 的 run_id",
  "language": "zh-CN",
  "device_models": {"硬盘盒": "用户给出的品牌和准确型号"},
  "test_notes": "用户的测试备注，可含换行。",
  "self_analysis": "用户自己的分析，可含换行。"
}
```

使用已有报告入口：

```bash
python3 scripts/report.py --input /path/to/results.json --user-input-file /path/to/user-input.json --output /path/to/final-report --language zh-CN --format pdf
```

也可将此对象写入派生结果的 `user_input` 字段；不改写原始 fio 数据。运行 ID 和报告语言必须匹配，换语言需用户同意或按其语言要求翻译并保留原意。保留补充 JSON 以便重生成；后续补充时合并用户已确认的内容，只删除用户明确要求移除的项。

HTML/PDF 在硬件配置后显示“用户补充”，设备型号标“用户提供”，保留原始检测记录用于追溯。补充型号不自动覆盖检测值或视为官方核实，也不会自动刷新参考缓存；执行 AI 根据新的型号重新研究资料并修订评价。若与已检测型号冲突，展示差异并核对，不静默替换。

文档与报告自查：无补充直接交付、仅主动补充/部分填写/全部填写、其他设备标签、换行与特殊字符转义、运行或语言不匹配、用户分析与测量区隔。PDF 沿用报告打印流程，交付前确认补充内容完整可读。
