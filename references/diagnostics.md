# 可选专项测试

普通 quick/full 默认不变。用户选择专项后，先用 `--dry-run` 展示目标、占用空间、累计写入上限、时限与保留空间，再按用户授权执行。添加测试能力不等于授权当场写盘。进度沿用当前对话语言；无法估算总时间时展示步骤完成度。

## 随机访问范围与重复读取

```bash
python3 scripts/benchmark.py --target /path/to/volume --output /path/to/new-results --profile mapping --language zh-CN --ui-language zh-CN --dry-run
```

默认初始化 256 GiB 文件，依次测试 8、64、256 GiB 地址范围；可用 `--file-size` 修改最大范围。每个范围分别以 QD1、QD16 做两轮 4 KiB 随机读取，固定随机种子，第二轮重复同一访问序列。每轮最多读 1 GiB、30 秒；达到时间上限可能只完成序列的一部分。报告展示速度、IOPS、p99 延迟，完整数据保留实际读取量与时长。比较前检查两轮实际读取量，不能把样本量差异当成缓存收益。

第一轮不是严格冷缓存：初始化及其他任务可能已使映射缓存变热。禁止声称测试能测出 DRAM 容量或隔离 DRAM 贡献；这是整盘对访问范围与重复访问的响应。板载 DRAM 容量单列为型号资料，附来源，不从本测试反推。初始化不完整即停止，不读取未写区域。

## 持续写入与空闲恢复

```bash
python3 scripts/benchmark.py --target /path/to/volume --output /path/to/new-results --profile cache --recovery-seconds 300 --language zh-CN --ui-language zh-CN --dry-run
```

复用缓存专项的参考资料预算、持续降速与稳定窗口判断，随后空闲指定秒数，再向同一个测试文件起始位置写入最多 8 GiB、30 秒。新增写入计入预演总预算；显式 `--write-budget` 覆盖两段总量，不偷偷突破。报告显示起始、末段、空闲后平均速度、空闲时长和可取得的温度。恢复段文件位置与盘内占用状态不同，空闲也同时允许降温与内部整理；这是实际恢复表现，不单独证明 SLC 或热降速。USB 链路可能限制写入压力，无拐点时保留未确认。

## 有限文件写入与完整读回校验

使用全新的专属普通文件，先确认计划文件大小、写入预算和时限，再按用户授权执行。

```bash
python3 scripts/benchmark.py --target /path/to/volume --output /path/to/new-results --profile integrity --file-size 8GiB --write-budget 8GiB --language zh-CN --ui-language zh-CN --dry-run
```

- 默认文件大小为 64 GiB；可用 `--file-size` 指定有限大小，`--write-budget` 必须覆盖该文件的完整写入。可用空间增加不会扩大计划文件，空间不足则停止。不能覆盖已有文件或访问原始设备。
- 计划文件之外保留 **10 GiB 或卷容量的 5%（取较大值）**，另留 64 MiB 文件系统余量。共用空间的 APFS 卷或后台写入可能消耗余量，运行时持续检查并停止越界。
- 顺序写入带 CRC32C 校验信息的数据，写完后独立完整读回校验。保留每块位置校验，首次错误立即停止；仅写入成功不算校验通过。校验写入有计算开销，不冒充普通顺序写入峰值。
- 写入与读取各默认最多 1800 秒，`--sustained-seconds` 可调整各阶段时限。任一阶段未覆盖计划字节数即失败，不能显示完整通过；复测必须新建运行目录。
- 输出写入量、校验覆盖量、状态、写入速度曲线及可取得的温度范围。失败读取的累计 I/O 字节不能冒充成功校验量；原始 stderr 保留错误位置与细节用于定位。
- 校验异常可提示数据完整性、连接或容量异常，不能直接断言假货。校验通过仅覆盖该测试文件的逻辑区域，不包括已有文件、隐藏备用块，也不能排除被控制器重映射的物理坏块。
- 短时跑完或传感器缺失不能称已完成热极限验证。定位散热影响时保持连接、数据量和占用状态一致，对照导热安装前后；不能仅凭温度与速度相关性下定论。

测试文件按现有流程移到系统废纸篓，移动不释放空间；交付对话说明实际占用与如何恢复空间，不自动清空废纸篓。报告正文只写测试发现。

fio 校验语义参考：[官方 Verification 文档](https://fio.readthedocs.io/en/latest/fio_doc.html#verification)。这些测试的硬件参考仍按每次识别、匹配本地缓存或搜索可信资料的流程获取，不写死本机型号。
